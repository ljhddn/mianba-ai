# 🎯 AI 模拟面试官（6 评委多模型版 · 分层调用 + 快速模式）

一个用 Streamlit 写的 AI 模拟面试应用，由 **6 家大模型评委**分**分层调用**协作完成一场真实感更强的面试：

- **真实性校验**：点「开始面试」后先调 DeepSeek 校验——上传的简历是不是有效简历、岗位 / 公司是否真实存在；虚构输入（如「睡觉专家」「宇宙无敌公司」）会用黄色 `st.warning` 拦住，不会进入面试
- **输入纠错**：校验的同时把错别字 / 拼音 / 英文缩写还原成 3 个真实候选岗位 + 3 个真实候选公司；岗位 / 公司确认是真实的才允许选「以上都不是，用我输入的」
- **专业评委人设**：DeepSeek 是面过 200+ 候选人的大厂技术面试官，通义是 HR 总监，智谱是创业公司 CTO，Kimi 是压力面面试官，豆包是客观中立的面试官助理，文心是专挑漏洞的资深技术面试官
- **按岗位方向出题**：Java 后端只问 Java 集合 / JVM / 并发 / Spring / MySQL / Redis / 项目；前端只问 JS 闭包 / CSS / React 或 Vue / 性能优化 / 工程化，不再所有岗位共用一套题
- **常见岗位快捷选择**：前端 / Java 后端 / Python / 产品经理 / 运营 / 公务员 一键填入应聘岗位，选中按钮变为强调色，也可以继续手动修改
- **出题（3 个快模型 + 5 位评审）**：在 3 个「快模型」（GLM / 文心 / Kimi）里随机抽 1 位当「主考官」按岗位方向 + 模式出题，5 位评审团（3 个快模型 + DeepSeek + 通义）并发投票，**≥3 票通过**才发给你；不通过就让投反对票的评委重写 **1 次**，仍不通过就换新题重新评审（最多 2 道），全部候选都不通过才回退第一道原题
- **打分（6 家全量，保质量）**：你答完后 6 位评委**同时**打分。项目 / 经历题按「技术深度 3 / 项目经验 3 / 沟通表达 2 / 逻辑思维 2」四个维度，四项相加 = 本题得分；技术原理题只评「技术深度 3 / 沟通表达 2 / 逻辑思维 2」三项并折算成 10 分制，**不评项目经验**；评分期间每位评委一张卡片显示「⏳ 正在评分...」，6 位全部结束后显示最终平均分（去掉最高最低）
- **快速模式**：设置页勾选「**快速模式（用小模型，快但简单）**」后，只用 GLM 一个模型完成所有出题 + 打分（没有独立评审团），用质量换速度
- **淘汰**：至少 3 位评委给出有效评分，且其中 **≥2 个 `continue=false`** 才立刻结束面试；超时 / 失败的评委不计入，避免网络抖动误淘汰
- **反问**：问完后可以向该公司面试官提问（薪资 / 加班 / 团队 / 晋升）
- **报告**：高亮最终平均分，分维度展示技术深度 / 项目经验 / 沟通表达 / 逻辑思维哪块弱，并给出「第 N 题 + 具体知识点 + 书名/章节」的改进建议
- **历史记录**：每次生成报告自动写入本地 `interview.db`；页面右上角 **📜 历史记录** 按分数排序查看全部记录，并用折线图看自己的进步趋势（不需要登录 / 云端）

## 功能

### 界面（深色极简）

- 全局是深蓝科技风（`#060c16` 底 + `#0b1523` 面板 + `#203047` 细边框），不叠加网格 / 斜线 / 光晕等装饰
- 面试页采用 **70% / 30% 左右分栏**：左栏是主考官头像（64px 圆形）+ 题目气泡 + 回答输入框 + 底部进度条；右栏是 6 位评委纵向卡片
- 右侧评委卡片显示 **32px 圆形小头像 + 分数**；评语默认折叠，点卡片里的「查看评语」展开维度分和评语
- 主考官出题时，左栏头像自动切换为对应 AI 在 `assets/` 下的二次元头像；头像文件缺失时回退灰色圆，不报错
- 设置表单在 820px 的深色卡片里；输入控件单独保持浅底深字，保证对比度
- 卡片内从上到下：应聘岗位、面试模式、公司规模、目标企业、上传简历、岗位 JD（选填）
- 应聘岗位上方有 6 个常见岗位快捷按钮：**前端 / Java 后端 / Python / 产品经理 / 运营 / 公务员**；未选中为灰色小按钮，点击后自动填入岗位并变为强调色，仍可手动修改
- 主操作按钮使用 `#4f7cff` 强调色，无阴影 / 渐变
- 右上角是 **📜 历史记录** 小按钮（展开后变成 **✖️ 收起历史**）
- 答题 / 反问输入框为**深底浅字**（`#09162c` 底 + `#e7efff` 文字），光标、placeholder 同步调亮
- 历史题目与回答折叠在页面底部；用户回答气泡继续使用 **🙋**
- 左侧边栏只有一个默认收起的 **⚙️ 高级设置** 折叠区，里面才显示评委列表、模型名、超时与 token 上限等技术参数
- 主页面不再堆「题量 3-8 题 / 出题 3 个模型 / 打分 6 个评委」这类技术说明

### 〇、真实性校验 + 输入纠错（开始面试前）

```
点「开始面试」
    ├─ 上传了简历 → 调一次 DeepSeek 判断是否有效简历
    │    └─ 不是简历 → 黄色警告「您上传的文件不是有效简历，请重新上传」，停在设置页
    └─ 岗位 / 公司 → 调一次 DeepSeek 判断是否真实存在
         ├─ valid     → 可以确认原输入，也可以选纠正后的真实候选
         ├─ uncertain → 只能从 3 个真实候选里选（没有「用我输入的」后门）
         └─ invalid   → 黄色警告「请输入真实的岗位和公司」，只能选真实候选 / 返回修改
```

- **简历校验**：只要上传了 PDF，就先调一次 DeepSeek 判断它是不是一份有效简历（看姓名 / 联系方式、教育经历、工作或项目经历、技能等要素）；风景图说明、乱码、小说、论文、菜单、合同等会直接提示 `您上传的文件不是有效简历，请重新上传`，不会开始面试
- **岗位 / 公司校验**：一次 DeepSeek 调用同时做「真实性判断 + 输入纠错」，要求返回 `{"job": {"status", "reason", "suggestions"}, "company": {...}}`：
  - `status` 只能是 `valid / uncertain / invalid`：`Java 后端开发`、`字节跳动` 是 `valid`；`java 后 Duan`、`jool` 这类拼写 / 缩写是 `uncertain`；`睡觉专家`、`宇宙无敌公司` 是 `invalid`
  - `suggestions` 固定给 3 个真实存在的候选；`status` 不是 `valid` 时不会重复用户原文，避免假输入被选回来
  - `valid` 时单选最后一项是「以上都不是，用我输入的」；`uncertain / invalid` 时**没有这个选项**，必须从真实候选里选
- **校验失败就不放行**：明显虚构、校验接口挂掉、模型输出无法解析，都会用 `st.warning` 黄色警告拦住；页面明确提示 `请输入真实的岗位和公司`，不会出题、不会进入面试
- **演示兜底（仅限服务不可用）**：只有校验调用失败 / 超时才出现「跳过校验，直接开始面试」按钮，点了才跳过且不做纠错；判定为 `invalid / uncertain` 时**没有**这个入口，仍然只能选真实候选
- **公司留空**：跳过公司校验，只校验岗位；公司填了就必须是真实候选（或确认真实后坚持原输入）
- 只用 **DeepSeek**（`VERIFY_JUDGE`）：岗位 / 公司校验 `temperature=0.0`、上限 `VERIFY_MAX_TOKENS=900`；简历校验 `temperature=0.0`、上限 `RESUME_CHECK_MAX_TOKENS=300`；确认之前**不会出题**
- 想改候选数量改 `VERIFY_ITEM_LIMIT`，想换校验模型改 `VERIFY_JUDGE`

### 一、6 位评委与「出题 / 打分」分层（密钥走 secrets / 环境变量，页面不暴露 Key）

| 评委 | 模型 | 人设 / 关注点 |
| --- | --- | --- |
| DeepSeek | `deepseek-chat` | 有 10 年经验的大厂技术面试官，面过 200+ 候选人 |
| 通义千问 | `qwen-plus` | HR 总监，看人准，关注候选人稳定性和沟通能力 |
| 智谱 GLM ⚡ | `glm-4-flash` | 创业公司 CTO，看重能不能直接上手干活（**快模型**，也负责快速模式） |
| Kimi ⚡ | `kimi-k2.6` | 压力面面试官，喜欢追问、挑刺（**快模型**） |
| 豆包 | `ep-20261016182931-bhl88`（火山方舟接入点 ID） | 面试官助理，负责记录和打分，客观中立 |
| 文心一言 ⚡ | `ernie-5.1`（欠费 / 不可用时自动换 `ernie-5.0`，已关闭 thinking） | 资深技术面试官，专挑方案漏洞、边界条件和线上事故（**快模型**） |

- 6 家的 `base_url` / `model` 固定在 `app.py` 的 `JUDGES` 字典里；`api_key` 从 `.streamlit/secrets.toml` 或同名环境变量读取，页面与侧边栏都没有 Key 输入框
- **缺 Key 自动降级**：只把配了 Key 的评委放进出题 / 评审 / 打分池，少配一两家也能跑；评审通过票数随人数自适应（5 人 3 票、3 人 2 票），不会因为少配模型导致全场出不了题。设置页会显示「已配置 N/6 位评委」
- **分层调用（默认）**：出题阶段只用 3 个快模型（`FAST_JUDGES`，即 GLM / 文心 / Kimi）；评审阶段用 5 位评审（`REVIEW_JUDGES` = 3 个快模型 + DeepSeek + 通义）；打分阶段才 `6 家全上`（`score_judges()`）——出题要快、打分要质量
- **限长**：出题 / 重写 / 评审投票 `max_tokens=320`（`QUESTION_MAX_TOKENS`，题目 + 3–5 个评分点）；打分 `max_tokens=560`（`SCORE_MAX_TOKENS`，四个维度 + 评分点 + 原话证据 + comment + continue）
- **超时**：每次 API 调用 `30` 秒超时（`REQUEST_TIMEOUT_SECONDS`），客户端不自动重试（`max_retries=0`）——超时就**跳过这位评委**，不一直等
- **模型名兜底**：
  - **豆包**：`model` 现在直接填火山方舟的接入点 ID（`ep-20261016182931-bhl88`）；如果它报「模型不存在 / 无权限」，把 `JUDGE_META["doubao"]["endpoint_id"]` 填成另一个接入点 ID（`ep-xxxxxx`），代码会自动用它重试一次
  - **文心一言**：主模型是 `ernie-5.1`；它需要千帆账户有可用余额 / 已开通。如果报「模型不存在 / 无权限 / account_overdue」，代码会自动再试 `ernie-5.0`（见 `JUDGE_MODEL_FALLBACKS`）；两个都不通就去千帆控制台确认余额 / 已开通的模型名。文心 5.1 / 5.0 是推理模型，代码已通过 `thinking: {"type": "disabled"}` 关闭思考，避免 `reasoning_content` 吃光 320/560 的 `max_tokens`
- **豆包**：真实测试发现默认思考模式下打分 30 秒超时；代码已同样关闭 `thinking`，实测约 5.7 秒返回合法 JSON（见 `JUDGE_EXTRA_BODY`）
  - 试通的模型会缓存下来，后续不再反复试错，错误提示里也会直接告诉你要改哪里
- 左侧 **⚙️ 高级设置** 里有 **🔌 自检 6 位评委** 按钮：并发调用 6 家接口各一次（token 消耗极小），一眼看出哪家的 Key / 模型有问题
- **调用温度**：每个环节本来有自己的温度（出题 / 评审投票 / 简历匹配度 `1.0`、打分 `0.3`、反问回答 `0.8`、综合点评 `0.7`、连通性自检 `0.0`、真实性校验 `0.0`）；**只有 Kimi 例外**：Kimi K2.6 关闭 thinking 后接口只接受 `temperature=0.6`，所以所有 Kimi 调用（含自检）都固定 `temperature=0.6`，其他 5 位评委的温度设置一个都没改——见 `app.py` 顶部的 `JUDGE_TEMPERATURE_OVERRIDE` 与 `JUDGE_EXTRA_BODY`

### 三、答题评分：四维度打分 + 6 位评委全量 + 评委卡片实时展示

- 6 位评委并发返回维度分 + 评分点 + 点评 + 是否继续：
  ```json
  {"technical_depth": 2, "project_experience": 2, "communication": 1, "logical_thinking": 1,
   "points": [{"point_id": 1, "status": "covered", "evidence": "候选人原话"}],
   "comment": "直接不客气的点评", "continue": true}
  ```
  技术原理题只返回三项：`{"technical_depth": 2, "communication": 1, "logical_thinking": 1, ...}`，不含 `project_experience`
- **证据化评分（评分点）**：主考官出题时给出 3–5 个评分点（不展示给用户）；评分时评委逐点判断 `covered / partial / missing`，并引用候选人原话。系统会校验引用是否真的出现在回答里（≥3 字），对不上的自动降级为「证据无效」，不计入覆盖。报告展示「4 个评分点覆盖 2 个」和逐点原话，比只看维度分更能说清「差在哪」。
- **维度满分**：项目题技术深度 3、项目经验 3、沟通表达 2、逻辑思维 2，**四项相加 = 该评委给本题的总分（满分 10）**；技术原理题只评 3/2/2 三项，由系统折算成 10 分制，项目经验显示「未考察」
- **未考察 ≠ 0 分**：某个维度本题确实考察不到时，评委给 `null`，系统只在真正考察到的维度上折算（例如技术题只拿到沟通 1 + 逻辑 1，折算为 5.0，而不是被技术深度的 0 分拉到 2.0）；模型漏给的维度同样按未考察处理
- **评委卡片实时更新**：打分仍走 `stream=True`，但页面不会显示模型返回的 JSON 原文；右栏每位评委一个卡片，显示 32px 头像与分数，评分中显示「⏳ 评分中」，评完后可展开「查看评语」看四维度分和独立评语。6 位评委全部完成后才显示最新平均分
- **本题最终分** = 6 位评委的总分去掉一个最高分和一个最低分，剩下 4 个取平均（例如 `4/5/6/7/8/9` → `(5+6+7+8)/4 = 6.5`）；有效分不足 5 个时直接取平均，避免「去掉最高最低后只剩 1 个分数」
- **评委分歧**：平均分会把分歧抹平，所以结果里同时显示「评委分歧 = 最高分 - 最低分」，报告页仍保留谁最严 / 谁最宽
- **打分温度 0.3**（`SCORE_TEMPERATURE`）：评分要可复现，不能像出题那样放开到 1.0；同一答案在不同场次的绝对分仍不建议直接比较
- **维度平均分**：全场所有评委、所有题目的每个维度分别取平均，用于报告页判断「哪块弱」
- **提前淘汰**：6 个 `continue` 里 **≥2 个 false** → 立即结束面试、跳过剩余题目与反问环节，直接生成并进入报告页，报告里写明是哪几位评委、依据是什么（不足 3 题时不会淘汰）
- **一致高分提前收尾**：无人投 false 且本题最终分 ≥ `8.5` → 评委认为问够了，直接进入反问环节（不必凑满 8 题）
- **动态题量**：最少 `3` 题、最多 `8` 题
- 你也可以在答题页勾选确认后点「🏁 提前结束并生成报告」主动收尾

### 四、反问环节（保留）

- 所有问题问完后，面试官会说「**面试环节结束，你有什么要问我的吗？**」
- 由**最后一道题的主考官**继续以该公司面试官身份回答：薪资构成（base / 年终 / 期权）、加班强度、团队氛围、晋升路径、技术栈等都可以聊；薪资只给区间与结构，不承诺 offer
- 结束方式：回复「没有了」（支持「暂时没有了，谢谢」「no more questions」等）或点击 **🏁 结束提问并生成报告**

### 五、报告页

- **最终平均分高亮**：深色总结卡片展示本场最终平均分（各题去极值后再取平均），旁边是题量、结束原因、简历匹配度
- **能力维度分析**：表格 + 黄色「最弱维度」提示，分维度展示技术深度 / 项目经验 / 沟通表达 / 逻辑思维的平均分、满分、得分率与「强 / 中 / 弱」评价
- **改进建议（按维度短板定位到具体题目）**：
  - 自动找到每个维度最低的那道题，例如「逻辑思维 1.0/2（弱）；最低的是第 3 题『……』（1.0/2）」
  - 技术深度会按具体题目关键词给学习材料：JVM → 《深入理解 Java 虚拟机》第 2 章；并发 → 《Java 并发编程实战》；Spring → 官方文档；MySQL / Redis 也各有对应资料
  - 项目经验 / 沟通表达 / 逻辑思维分别给 STAR 重写、结论先行 + 三点式、因果链与边界条件的具体练法
- **逐题明细**（每道题一个折叠块）：
  - 谁出的题（主考官）+ 是否经过重写（含原题内容、"重写 1 次后通过"或"1 次重写仍未通过，已回退原题"）
  - **5 位评审的投票结果**表（评审 / 结论 / 理由，逐轮展示；快速模式这里会写明「没有独立评审团」）
  - 你的回答
  - **6 位评委的独立分数与评语**表（评委 / 独立分数 / 四个维度分 / 是否继续 / 评语；快速模式只有 1 位评委）
  - 本题最终分 + 本题维度平均分 + 本题作答用时 + 投「结束」的评委意见
  - **本题评分点覆盖（N/M）**：每个评分点「说到 / 说了一半 / 没说」，以及评委引用的一句候选人原话；证据对不上原文的会标为无效
- **6 位评委独立评分总览**：每位评委在各题的分数序列与平均分，并标出 🔻最严格 / 🔺最宽容（快速模式只有一行）
- **反问环节记录** + **AI 综合点评**：AI 被要求写 3-5 条具体建议，每条必须包含「具体题目 / 知识点 + 书名与章节或官方文档 + 可直接照说的示范回答」
- **本场运行指标**：调用次数 / 失败次数 / 平均与 P95 延迟 / 估算 token，按环节拆分（出题 / 评审 / 打分 / 反问 / 综合点评）
- **能力项覆盖表**：本场覆盖 N/M 个能力项，逐项标「已覆盖 / 未覆盖」及对应题号
- **再练一次最弱一题**：自动选中本场得分最低的题，重新作答后 6 位评委再评一次，显示「原分 → 新分」、四个维度变化、评分点从「没说」到「说到」的变化；不写历史、不改原报告（每次重答 6 次调用）
- 支持 **⬇️ 下载报告（Markdown）**，导出的文件包含全部客观数据、维度分析、改进建议、投票表与各评委明细

### 六、本地历史记录（SQLite，自动保存）

```
ai-mock-interview/interview.db
└── interviews
    ├── id              自增主键
    ├── job             岗位
    ├── company         公司
    ├── mode            面试模式
    ├── score           最终平均分
    ├── questions_count 实际问答轮数
    └── created_at      记录时间
```

- 使用 Python 自带的 `sqlite3`，**不需要安装数据库服务器**；数据库文件就在项目目录，应用启动时自动创建 `interview.db` 和 `interviews` 表
- 每次进入报告页（提前淘汰 / 主动结束 / 问满上限 / 反问结束）都会自动写入一条记录；`history_saved` 标记保证「重新生成 AI 点评」不会重复插入
- 页面右上角 **📜 历史记录**：
  - 顶部显示总场次、最高分、最近一场
  - 表格按分数从高到低展示排名、岗位、公司、模式、分数、题数、时间
  - 另附按时间排序的分数折线图，并显示「第 1 场 → 最近一场」的累计变化和较上一场变化
- 纯本地文件，没有用户登录、没有云端同步；左侧 **⚙️ 高级设置 → 本地数据** 可一键清空全部历史（模拟面试 + 复盘），也可以直接删除 `interview.db`
- 清空入口需要一个「我确认清空本机历史记录」开关，避免误删；清空只影响本机 SQLite，不会调用任何外部服务
- 可用环境变量 `INTERVIEW_DB_PATH` 指定其他数据库路径；`smoke_test.py` 会自动使用临时数据库，不会污染真实历史

### 七、其他保留功能

- 应聘岗位输入、面试模式（HR 面 / 技术面 / 压力面）、公司规模（大厂 / 中型公司 / 创业公司）、目标企业名称（选填）
- **岗位 JD（选填）**：粘贴招聘网站原文，会进入出题 / 评审 / 打分的背景块，让问题贴 JD 的职责与技能要求；不粘也不影响使用
- 上传 PDF 简历（选填）：`PyPDF2` 解析文本（最多 4000 字）后作为评委们的「简历参考」，报告里会给 0-100 的**简历匹配度评分**
- **答题计时**：每题出现后显示一条 2 分钟计时条；真实作答用时由服务端记录，写进报告（平均用时 + 逐题用时）
- **运行指标**：每次模型调用记录环节 / 评委 / 模型 / 耗时 / 成功失败 / 估算 token；报告页和侧边栏显示调用次数、失败次数、平均 / P95 / 最慢延迟，答辩时可以直接给数字
- 状态持久化（`st.session_state`）；调用失败会回滚本轮并可重试；AI 综合点评失败可在报告页一键重新生成

### 八、快速模式（设置页的复选框）

```
☐ 不勾选（默认）：分层架构 = 3 个快模型出题 + 5 位评审投票 + 6 位评委全量打分
☑ 勾选「快速模式（用小模型，快但简单）」：只用 GLM 一个模型出题 + 打分
```

- 勾选后：`writer_pool()` = `review_panel()` = `score_judges()` = `["glm"]`——**出题 1 次调用、没有评审投票、打分 1 次调用**，是本项目最快的跑法
- 本题最终分 = 这一位评委的分数（有效分不足 5 个时不做去极值）
- 只有 1 位评委，所以「≥2 票 false 提前淘汰」不会触发（不会误杀）
- 反问回答 / 简历匹配度 / 综合点评也统一换成这个小模型（`judge_preference()`）
- 侧边栏与报告标题会显示本场架构（`architecture_label()`），方便你回顾这场是「分层」还是「快速」

## 并发与容错

| 环节 | 并发方式 | 失败处理 |
| --- | --- | --- |
| 5 位评审投票 | `ThreadPoolExecutor` 同时发 5 个请求 | 失败按「未通过」计，理由里带上错误原文 |
| 3 位评委重写 | 同时发 3 个请求 | 全部失败则保留当前题目 |
| 6 位评委打分 | 同时发 6 个请求，每人一条流式通道边生成边刷新页面 | 失败 / 超时的不计入平均（去极值只在有效分数上做），页面给出提示 |
| 6 位评委自检 | 同时发 6 个请求 | 逐家显示状态与错误 |
| 单评委调用（真实性校验 / 出题 / 反问 / 综合点评 / 简历匹配度） | 本身就是一次请求；失败时按顺序换一位评委兜底 | 换人重试，仍失败才报错 |

- **每次调用 30 秒超时**：超时的那位评委直接跳过（错误里写明「超时（>30s），已跳过」），整场面试继续；打分阶段还有总兜底 deadline，到点就返回，不等还在跑的线程
- 只有「一位评委都联系不上」时才回滚本轮，不会因为某一家挂掉就中断整场面试
- 真实性校验失败（调用报错 / 输出无法解析 / 判定不是真实岗位或公司）不会放行：页面用黄色 `st.warning` 提示并停在设置页；只有从 3 个真实候选里选一个（或原输入被判定为 `valid`）才允许开始面试
- 历史记录写入失败（例如 `interview.db` 被占用）只会在报告页提示，不影响报告本身；重新生成 AI 点评时会再尝试写入
- 豆包模型名不通时自动改用接入点 ID（`ep-xxx`）重试，并把可用模型写入 `session_state` 复用

## 快速开始

1. 安装依赖

   ```bash
   pip install -r requirements.txt
   ```

   `requirements.txt`：`streamlit>=1.36`、`openai>=1.30`、`PyPDF2>=3.0.1`

2. 配置评委 Key（至少 1 家；推荐 6 家全配）

   新建 `.streamlit/secrets.toml`（已在 `.gitignore` 里，不会进 Git）：

   ```toml
   DEEPSEEK_API_KEY = "sk-..."
   QWEN_API_KEY = "sk-..."
   GLM_API_KEY = "..."
   KIMI_API_KEY = "sk-..."
   DOUBAO_API_KEY = "ark-..."
   WENXIN_API_KEY = "bce-..."
   ```

   也可以用同名环境变量注入，适合 Docker / 云平台：

   ```bash
   export DEEPSEEK_API_KEY=sk-...
   ```

   - **没有 secrets.toml 也不会崩**：`_secret()` 安全回退到环境变量；一个 Key 都没有时页面会提示「没有检测到任何评委的 API Key」，而不是白屏
   - 设置页 / 侧边栏会显示「已配置 N/6 位评委」；未配置的评委自动跳过，评审通过票数按人数自适应（5 人 3 票、3 人 2 票）
   - 页面上没有 Key 输入框，换 Key 改 secrets / 环境变量后重启即可

   豆包的模型名如果不可用，填一下 `JUDGE_META` 里的接入点 ID：

   ```python
   JUDGE_META = {
       "doubao": {"label": "豆包", "persona": "...", "endpoint_id": "ep-2025xxxx-xxxxx"},  # ← 填 ep-xxx
       ...
   }
   ```

   文心（千帆）的模型名如果不可用，改 `JUDGE_MODEL_FALLBACKS` 里按顺序尝试的兜底模型名：

   ```python
   JUDGE_MODEL_FALLBACKS = {
       "wenxin": ["ernie-5.0"],  # ernie-5.1 欠费 / 不可用时自动再试这个
   }
   ```

   > ⚠️ 提交 / 上传前检查：`.streamlit/secrets.toml` 和 `interview.db` 都已在 `.gitignore` 里，
   > 但**打 zip 不受 .gitignore 约束**。投递作品前请确认包里没有二者（数据库里有真实问答，
   > secrets 里有真实 Key），并去各家控制台轮换一次已经外发过的 Key。

3. 启动应用

   **Windows 推荐**：双击 `启动.bat`（或 `start.bat`），会自动起服务并打开浏览器；想用独立窗口（没有浏览器地址栏）就双击 `启动_桌面窗口.bat` / `start_desktop.bat`，它会优先用 Edge/Chrome 的 `--app` 模式打开，**不需要额外安装**；如果装了 pywebview，会优先用 pywebview 窗口。

   也可以命令行启动：

   ```bash
   streamlit run app.py
   ```

   浏览器会自动打开 <http://localhost:8501>。Web 应用本身就是软件形态，不需要额外做成桌面程序。

## 使用流程

1. （可选）展开左侧 **⚙️ 高级设置**，点 **🔌 自检 6 位评委**，确认 6 家模型都能正常调用
2. 在设置卡片里填写**应聘岗位**（也可以点上方「前端 / Java 后端 / Python / 产品经理 / 运营 / 公务员」快捷按钮自动填入，再手动改），选择**面试模式**与**公司规模**；选填**目标企业**、选填**上传简历 PDF**、选填**岗位 JD**；想快一点就在高级设置里勾上 **快速模式（用小模型，快但简单）**
3. 点击 **🚀 开始面试**：先进入 **🧾 真实性校验** —— 上传了简历就先判断是不是有效简历；然后 DeepSeek 判断岗位 / 公司是否真实存在，并给出 3 个真实候选。校验不通过会用黄色 `st.warning` 提示「请输入真实的岗位和公司」；`valid` 时可选「以上都不是，用我输入的」，`uncertain / invalid` 时只能选真实候选。确认后点 **✅ 确认并开始面试**；想改输入就点 **↩️ 返回修改输入**
4. 确认之后评委才开始出题 —— 在 3 个快模型里随机抽主考官出题 → 5 位评审投票（≥3 票通过）→ 票数不够就重写 1 次；页面左栏显示题目和主考官头像，右栏是评委评分卡片，出题评审过程可在下方「历史题目与回答」里展开查看
5. 在左栏输入框写下回答 → 点击 **提交回答**：6 位评委同时打分，右栏 6 个评委卡片实时更新（评分中显示「⏳ 评分中」，评完显示分数；评语默认折叠，点「查看评语」展开）；全部评完后显示最新平均分；左栏底部进度条同步更新
6. 循环第 5 步，直到：**≥2 位评委投 false（提前淘汰，直接进报告页）**、**问满 8 题**、**一致高分提前收尾（进反问环节）**，或你主动提前结束
7. **反问环节**：向面试官提问（薪资 / 加班 / 团队 / 晋升），逐条得到回答；回复「没有了」或点击 **🏁 结束提问并生成报告**
8. 在报告页查看：高亮的最终平均分、能力维度分析（技术深度 / 项目经验 / 沟通表达 / 逻辑思维哪块弱）、定位到具体题目的改进建议、逐题的主考官与 5 位评审投票、6 位评委的独立分数与四维度分、评委严格度对比、反问记录与 AI 综合点评；可下载 Markdown
9. 点页面右上角的 **📜 历史记录**：按分数查看所有历史记录，并用折线图看自己的进步趋势；再点 **✖️ 收起历史** 收起
10. 点击侧边栏 **🔄 重新开始** 或报告页的 **🔄 再来一场面试**，即可开启新一场

## 接口调用一览

| 环节 | 参与的评委 | 返回格式 |
| --- | --- | --- |
| 简历有效性校验 | 固定 **DeepSeek**，上传简历时 1 次（`temperature=0.0`、300 token） | `{"is_resume": true/false/null, "reason": "..."}` |
| 岗位 / 公司真实性校验 + 输入纠错 | 固定 **DeepSeek**，开始面试前 1 次（`temperature=0.0`、900 token） | `{"job": {"status": "valid|uncertain|invalid", "reason": "...", "suggestions": ["...", "...", "..."]}, "company": {...}}` |
| 出题 | 1 位主考官，**只从 3 个快模型里抽**（失败时依次换人兜底），`max_tokens=320` | `{"question": "...", "rubric": ["评分点1", "评分点2", "评分点3"]}`（JSON Output） |
| 评审投票 | **5 位评审**并发（3 个快模型 + DeepSeek + 通义，含主考官本人复查），`max_tokens=320`；快速模式没有这一步 | `{"pass": true/false, "reason": "..."}` |
| 重写题目 | 投「不通过」的评委并发，`max_tokens=320` | `{"question": "...", "rubric": [...]}` |
| 答题评分 | **6 位评委**并发 + `stream=True`，完成后用卡片展示总分 / 四维度 / 评语，`max_tokens=560`；快速模式只有 GLM 1 位 | `{"technical_depth": 0-3, "project_experience": 0-3, "communication": 0-2, "logical_thinking": 0-2, "points": [{"point_id": 1, "status": "covered|partial|missing", "evidence": "原话"}], "comment": "...", "continue": true/false}` |
| 反问回答 | 最后一位主考官（失败时换人） | 普通文本，口语化作答 |
| 简历匹配度 | 1 位评委（有简历时才调用） | `{"resume_match_score": 0-100, "resume_match_comment": "..."}` |
| AI 综合点评 | 1 位评委代表招聘委员会执笔 | 普通文本（Markdown） |

上面每一次调用都带 `timeout=30`（`REQUEST_TIMEOUT_SECONDS`），并且客户端 `max_retries=0`：超时直接判定该评委失败并跳过，绝不无限等。

返回内容会被 `load_json_object()` 清洗（兼容 ```json 包裹与前后多余文本），分数裁剪到 1-10、`continue` 做三态解析；解析失败时该评委按「弃权 / 未评分」处理，不会让整场面试崩掉。

## 已知限制

- **不同场次的绝对分不可直接比较**：主考官随机、评委组合也可能不同，历史折线图的趋势要结合题目难度看；报告里已同时给出评委分歧
- **单机 SQLite**：`interview.db` 是本地文件，多用户部署会共享同一份历史；要上多用户请换成 Postgres 并按用户隔离
- **样式依赖 Streamlit 内部 testid**：深色主题用了 `data-testid` / `:has()`，升级 Streamlit 后需要回归一次视觉
- **真实性校验是 LLM 判断**：新岗位、小众公司可能被判 `uncertain`；校验服务不可用时页面会给出「跳过校验」入口（只有服务故障时才有，虚构输入仍然拦住）
- **评分点覆盖依赖模型按格式输出**：模型不给 `points` 时覆盖度会显示 0，但维度分照常计算；证据校验只做「原文是否出现」，不能判断引用是否偷换语境
- **运行指标是进程级**：单机演示够用，多用户部署会混在一起；token 按字符估算，不是账单金额
- **能力项覆盖依赖模型返回合法 topic**：不合法时按题目关键词 / 未覆盖项兜底，仍可能标错；覆盖表用于自查，不是严格考试大纲

## 常见问题

- **点「开始面试」为什么先跳到真实性校验页**：点按钮后会先调 DeepSeek 做校验——上传了简历就先判断是不是有效简历；岗位 / 公司则判断是否真实存在，并给出 3 个最接近的真实候选。`valid` 时你可以坚持原输入；`uncertain / invalid` 时没有「以上都不是」后门，必须选择真实候选。校验不通过会用黄色警告提示「请输入真实的岗位和公司」，不会开始面试；点「返回修改输入」可以回去重填。公司留空时只会让你确认岗位。
- **为什么填「睡觉专家」「宇宙无敌公司」不能开始面试**：DeepSeek 会把这些输入判定为 `invalid`（明显虚构 / 恶搞），页面会显示黄色警告并只给真实候选；如果不选真实候选，就不会出题。校验接口**调用失败**时会显示「跳过校验，直接开始面试」的兜底入口（不会做纠错）；判定为虚构或输出无法解析时没有这个入口。
- **为什么同一岗位的题和以前不一样了**：现在会先用 `detect_job_track()` 识别岗位方向，把「本岗位出题范围」写进主考官与评审的 prompt。Java 后端只问 Java 集合 / JVM / 并发 / Spring / MySQL / Redis / 项目；前端只问 JS 闭包 / CSS / React 或 Vue / 性能 / 工程化。评审团会把不在范围内的题判为不通过。
- **维度分怎么算**：项目题按技术深度 3 + 项目经验 3 + 沟通表达 2 + 逻辑思维 2 = 10 分；技术原理题只评技术 3 / 沟通 2 / 逻辑 2，三项折算成 10 分制，项目经验记为「未考察」。每位评委先给维度分，系统得到该评委的总分；有效分 ≥5 个时去掉一个最高分和一个最低分再平均，不足 5 个时直接平均。报告页的维度平均分只统计真正考察过该维度的题目。
- **改进建议里的书名 / 章节怎么来的**：系统会找每个维度最低的那道题，先按题目关键词匹配具体资料（JVM → 《深入理解 Java 虚拟机》第 2 章；并发 → 《Java 并发编程实战》；前端闭包 → MDN；CSS → MDN BFC/Flex/Grid 等），再把维度数据和逐题明细交给 AI 主审，要求每条建议都写「具体题目 + 学习材料 + 示范回答」。
- **历史记录存在哪里，怎么清空**：存在项目目录的 `interview.db`（SQLite 单文件），表名 `interviews`；没有登录、没有云端同步。想清空直接删除 `interview.db`，下次启动会自动重建空表。也可以用环境变量 `INTERVIEW_DB_PATH` 指向别的路径。
- **为什么历史页没有刚才这一场**：历史记录只在进入报告页（生成报告）时写入；如果还在答题 / 反问阶段，或者报告生成前就关掉了页面，就不会有记录。报告页顶部会显示「本场已保存到本地历史记录」。
- **某位评委报「调用失败」**：先展开左侧 **⚙️ 高级设置**，点 **🔌 自检评委**，看是哪家的问题（Key 无效 / 余额不足 / 模型名不对）。豆包报模型不存在时按上面填 `endpoint_id` 即可；文心报模型不存在 / `account_overdue` 时代码会自动从 `ernie-5.1` 换试 `ernie-5.0`，两个都不通就去千帆控制台确认余额 / 已开通的模型名（或改 `JUDGE_MODEL_FALLBACKS`）。
- **为什么有的题目标着「重写版」/「换题」**：主考官出的原题没拿到 3 票（5 位评审里至少要有 3 票通过），会先让反对的评委重写 1 次；仍不通过就重新生成新题再评审（最多换 2 道），全部候选都不通过才回退第一道原题。展开「评审过程」能看到每轮谁投了不通过、理由是什么。
- **为什么只问了 3 题就结束**：要么有 2 位以上评委认为你与岗位不匹配（报告里会写明依据），要么 6 位评委一致给了 ≥8.5 的高分、认为不用再问。
- **答完题后为什么先显示「⏳ 评分中」**：打分阶段仍然用 streaming 请求，但页面只在评委完成后展示解析好的分数；点「查看评语」才展开四维度分与评语，不会把模型返回的 JSON 原文或字段名显示出来；6 位评委全部完成后才显示最新平均分。
- **Kimi 返回的不是标准 JSON 怎么办**：会先去掉 ` ```json ` / ` ``` ` 代码块标记再解析；仍失败时用正则从文本里提取四维度分、总分、评语和 `continue`；完全提不出来时默认 **5 分**，评语写「评分格式解析异常」，不会直接弃权。其他评委仍按原规则处理。
- **快速模式和默认有什么区别**：默认是分层架构（3 个快模型出题 + 5 位评审投票 + 6 家全量打分）；勾选「快速模式（用小模型，快但简单）」后只用 GLM 一个模型出题 + 打分，没有评审团、分数也只有一位评委给——快很多，但结论更单一。侧边栏会显示当前是哪一种。
- **某位评委一直不返回怎么办**：每次调用都有 30 秒超时，超时的那位会被直接跳过（页面会写「超时（>30s），已跳过」），剩下的评委照常打分，不会卡住整场面试。
- **6 位评委分数差很多怎么办**：应用会去掉一个最高分和一个最低分再取平均，避免某一家过严或过松影响本题最终分；评分卡片会直接显示「评委分歧 = 最高分 - 最低分」，报告页的「最严格 / 最宽容」也会标出差异。
- **简历传上去提示「解析失败」或「不是有效简历」**：文件损坏 / 加密 / 不是真正的 PDF；图片 / 扫描版简历没有文字层，PyPDF2 取不到内容，无法校验；或者 DeepSeek 判断文件不是简历（风景图、小说、乱码等）。页面会用黄色警告停在设置页，请换一份可复制文字的 PDF 简历，或清空简历后重试。
- **想改题量 / 票数门槛 / 速度**：改 `app.py` 顶部的 `MIN_QUESTIONS`、`MAX_QUESTIONS`、`REVIEW_PASS_VOTES`、`ELIMINATE_FALSE_VOTES`、`EARLY_STOP_SCORE`；想让出题更快就改 `FAST_JUDGES`（主考官候选）、`REVIEW_JUDGES`（评审团成员）、`MAX_REWRITES`、`QUESTION_MAX_TOKENS` / `SCORE_MAX_TOKENS`、`REQUEST_TIMEOUT_SECONDS`，想换快速模式用的模型改 `QUICK_MODE_JUDGE`。想给某位评委单独设调用温度，把它写进 `JUDGE_TEMPERATURE_OVERRIDE`（Kimi 现在是 `0.6`；没写进去的评委一切照旧）。
